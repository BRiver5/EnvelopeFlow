# EnvelopeFlow — План реализации

> «Budget in envelopes. When one runs dry, see exactly where the slack is.»
> Офлайн-бюджет по методу конвертов с жадным алгоритмом перераспределения
> бюджета между конвертами при перерасходе — не просто список трат с лимитом.

---

## 0. Архитектурные решения

### 0.1 Полностью локальное приложение

Бэкенда нет и не нужен. Источник правды — `expo-sqlite` на устройстве. Никакой
регистрации, никакого обязательного интернета. Единственные системные
возможности за пределами локального экрана — **локальные уведомления**
(дневное напоминание залогировать траты) и **вибрация** (haptics на сохранении/
применении плана).

### 0.2 Разрешения — по умолчанию минимум

| Разрешение | Зачем (или "не используется") |
|---|---|
| `POST_NOTIFICATIONS` | опциональное дневное напоминание "залогируй траты" (Settings → Daily reminder) |
| `VIBRATE` | тактильный отклик на сохранение траты / применение плана перераспределения |

Всё остальное из `android.blockedPermissions` шаблона остаётся заблокированным
— приложению не нужны ни геолокация, ни камера, ни контакты.

### 0.3 Никаких точных будильников

`expo-notifications` с `DAILY`-триггером (`scheduleDaily`). Не `SCHEDULE_EXACT_ALARM`.

## 1. Стек

- Expo SDK 54 (TypeScript), expo-router
- `react-native-reanimated`, `react-native-svg` — гейдж конвертов, графики Stats
- `expo-sqlite` — единственное хранилище (envelopes/transactions/transfers/app_settings)
- `expo-notifications`, `expo-haptics` — опциональное напоминание, тактильный отклик
- Без Zustand — состояние каждого экрана помещается в локальные `useState` + `useFocusEffect`-перезагрузку из SQLite

## 3. Модель данных

| Таблица | Поля |
|---|---|
| `envelopes` | id, name, icon, target_cents, priority, rollover, archived, created_at |
| `transactions` | id, envelope_id, amount_cents, note, day, created_at |
| `transfers` | id, from_envelope_id, to_envelope_id, amount_cents, month, created_at — перераспределение БЮДЖЕТА месяца, не реальных денег |
| `app_settings` | key, value — monthlyIncomeCents, reminderEnabled, reminderHour |

Правило: никаких сгенерированных/демо-записей в статистике или списках.
Пустое состояние показывает `EmptyState`, а не заглушку.

## 4. Экраны

1. **Home** (`index.tsx`) — hero-блок (месяц, кольцо расхода), список конвертов с гейджем, баннер "needs rebalancing", кнопка Add expense
2. **Add expense** (`add-transaction.tsx`, модалка) — выбор конверта чипами, сумма, день (Today/Yesterday), заметка
3. **Envelope detail** (`envelope/[id].tsx`) — состояние месяца, перенос, история трат с удалением
4. **Rebalance** (`rebalance.tsx`) — план перераспределения (жадный алгоритм), анимированная визуализация потока, применение
5. **Stats** (`stats.tsx`) — 5 секций: on-budget rate (кольцо), тренд по месяцам (бар), расходы по конвертам (донат), heatmap по дням, Wilson-gated "что надёжно"
6. **Settings** (`settings.tsx`) — доход (справочно), управление конвертами (создание/правка/приоритет/rollover), напоминание, сброс данных

(6 экранов — верхняя граница правила "4-6", оправдана отдельным экраном Rebalance под основной алгоритм.)

## 5. Алгоритмическое ядро (`src/lib/`)

- **`envelopeMath.ts`** — последовательный расчёт состояния конверта по месяцам
  (`computeStateHistory`): rollover переносит и долг, и излишек, если включён;
  если выключен — каждый месяц честный чистый старт.
- **`rebalance.ts`** — `suggestRebalance()`: жадный алгоритм с защитой по
  приоритету — дефициты закрываются от самого важного конверта, излишек
  забирается с самого НЕважного донора первым. Типизированный результат
  `balanced | resolved | partial` — не скрывает нехватку излишка молча.
- **`envelopeStats.ts`** — Wilson-gated надёжность конверта "уложился в
  бюджет" по истории месяцев, двунаправленный `evaluateStandout` (above/below)
  с честным 3-статусным результатом (`found | insufficientData | notSeparated`)
  — тот же принцип "не ври об исходе", что в HeadMap/Readalike/BreathEasy.

19 юнит-тестов (`node --test`) покрывают rollover-цепочки, перераспределение
бюджета между конвертами, приоритетную защиту в `suggestRebalance`, и оба
честных null-статуса `evaluateStandout`.
